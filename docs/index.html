Your agent pays for its memory on every turn.

arricurdAI is an open-source memory layer for coding agents. It decides which memories enter the context, in what form and when, and it measures whether each one saves more tokens than it costs.

The name comes from arricurdari, Sicilian for “to remember”.

What a memory really costs

  • Written to the cache once, at 1.25×
  • Read again on each later turn, at 0.1×
  • Not loaded yet

      Load it now, or wait until it is needed?

      Waiting is not free. Fetching later costs an extra round trip, and every round trip re-reads the whole conversation. arricurdAI loads a memory up front only when that costs less than the trip it would probably need later.

      load now if size < p × (0.1 × conversation + 300) / ((1 − p) × (1.25 + 0.1 × turns left))

      claude-mem measured the same effect with fixed size limits: blocking whole-file reads cost 20% more tokens on a 19 KB file with Opus, and saved about a third on a 49 KB file (their evaluation). The limit should move with the conversation, and here it does.

      How it works

      arricurdAI does not replace the memory you already have. It sits between your memory stores and the agent's context, and decides what goes in.

      1. Gather candidates

        Hybrid search over the memory you already keep: CLAUDE.md, Claude Code auto memory, claude-mem observations, notes anchored to code.

      2. Price each one

        Rent for the turns left, freshness from code anchors, so a changed function lowers the value, and a probability of use learned from past sessions.

      3. Choose the form

        Nothing, a one-line pointer, a short summary or the full note, within a budget per turn. Nothing is often the right answer.

      4. Measure the return

        Each memory shown is checked against the tool calls that follow. Memories that cost more than they save are proposed for pruning.

      We publish a number only after measuring it

      The benchmark runs Claude Code on real repositories, with and without arricurdAI, and anyone can run it again from the arricurdai-bench repository.

      • Five open-source repositories in different languages, each with a working test suite.
      • Five linked sessions per repository: the first explores an area, the next ones come back to it with different changes.
      • Three setups on the same tasks: no memory, Claude Code native memory, and arricurdAI.
      • Same model and instructions, three runs per session, every transcript kept.
      • Price-weighted tokens per task, success rate and turns, with 95% confidence intervals.
      • The headline compares against Claude Code native memory, not against no memory, and tasks where arricurdAI costs more are published too.

      Works with what you already use

      Each of these tools does one part well. arricurdAI reads from them and adds the part none of them covers: what a memory costs over a session, and whether it paid off.

      ToolBest atWhat arricurdAI adds
      Claude Code native memoryInstructions loaded every session, and an index Claude writes itselfRanking against each request, and a check on which lines are ever used
      claude-memCapturing what the agent did, with layered recallA load-or-wait limit that moves with the conversation, and a return per memory
      legendary-mcp, omni-memoryNotes anchored to code that go stale when the code changesFreshness used as a price, next to rent and probability of use
      mem0, Zep and GraphitiLong-term memory for conversations and business dataCosts that account for turns and the prompt cache in coding sessions
